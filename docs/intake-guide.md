# Intake Guide

Use this guide when a celebrant project starts with a messy folder, scattered exports, or incomplete notes.

## Goal

Turn uneven source material into a clean set of canonical project docs.

## First Pass Checklist

Look for:

- business name
- celebrant name
- domain
- email
- phone
- social handles
- service list
- fees
- areas served
- strapline or key message
- supplied biography copy
- FAQ content
- design preferences
- reference websites
- logos and portraits
- asset permissions or restrictions
- background and video preferences
- desired contact mailbox and form locations

## Common Problems

### Duplicate Information

You may find the same facts repeated across PDFs, copied emails, and markdown notes.

Keep the strongest or most complete version in the canonical brief.

### Conflicting Information

If two source files disagree, note the conflict in working notes and choose the best-supported version for the draft brief.

### Too Much Copy

Do not assume every paragraph belongs on the website.

Protect the information architecture and reduce duplication across pages.

### Uneven Image Quality

Client folders often contain oversized, poorly cropped, or inconsistent images.

Keep the useful ones, note the weak ones, and define sensible fallback imagery in the design system. Record every selected generated or stock asset in the asset manifest before it enters the build.

## Canonical Output Docs

Once intake is complete, the key information should live in these documents:

- `client-brief.md`
- `reference-analysis.md`
- `design-system.md`
- `master-prompt.md`
- `build-prompt.md`
- `brochure-plan.md`
- `assets/asset-manifest.md`

The raw folder can remain messy after that.
