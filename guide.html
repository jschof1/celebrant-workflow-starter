Celebrant Workflow Starter Guide

This repository is a repeatable system for building bespoke celebrant websites and brochures from messy client folders. The key idea is simple: raw material goes in, canonical docs come out, the site is built from those docs, and the brochure follows once the website is stable.

What This Repo Is

A workflow starter, not a finished template

This repo is meant to be cloned for each new celebrant project. It gives you a reliable process, a shared ruleset, AI guidance via AGENTS.md, and a project skill under .cursor/skills/celebrant-workflow/.

The docs are the source of truth. The raw intake folder is allowed to be messy.

First Files To Read

For humans and agents

  • AGENTS.md for the repo-wide workflow and non-negotiables
  • docs/celebrant-website-guidelines.md for the core rules
  • docs/workflow-overview.md for the end-to-end process
  • docs/intake-guide.md for handling messy folders
  • guide.html for the visual handoff overview

1. Intake

Drop all raw client material into intake/raw-client-files/.

PDFs, docs, logos, images, screenshots, copied emails, and random notes are all fine.

2. Canonical Docs

Turn the raw material into clean project docs using the templates in docs/templates/.

Once this is done, the build should not depend on digging through the raw folder.

3. Build + Brochure

Build the site in site/ from the docs, then produce the brochure from approved copy, imagery, and design tokens.

How The Workflow Actually Runs

Recommended order

  1. Clone the starter for a new client repo. Keep one repo per celebrant project.
  2. Put all client material in the intake folder. Do not try to perfect the folder structure first.
  3. Fill out the canonical docs. Start with the brief, then reference analysis, design system, master prompt, build prompt, and brochure plan.
  4. Use the rules in docs/celebrant-website-guidelines.md. They cover APC requirements, British English, imagery limits, copy duplication, motion, and brochure print-safety.
  5. Use the project skill. The skill tells the agent to read the docs in the right order and keep the build grounded in them.
  6. Build the website in site/. The site should reflect the client, not a generic celebrant template.
  7. Create the brochure after the site stabilises. Brochure copy should draw from the approved site and the brochure plan.

Non-Negotiables

Rules that must survive every project

  • Use British English throughout.
  • Do not introduce em dashes unless the client already used them.
  • Include APC branding requirements and the required footer credit.
  • Avoid priests and risky licensed imagery.
  • Do not dump the same copy across Home, About, and Services.
  • Use visible animation thoughtfully, but keep native browser scroll.
  • Keep brochure styling safe for Affinity and similar vector editors.

Messy Folder Rule

Raw input can be ugly

The workflow is designed for chaotic Drive exports and half-organised client folders. Duplicate files, old notes, weird filenames, mixed image quality, and repeated facts are normal.

The job is to extract the important parts into the canonical docs, not to preserve the chaos.

AI Tool Setup

How to make this repo work well with agent tools like Gemini

Use AGENTS.md

Put repo-wide workflow instructions in AGENTS.md. This is the first thing an agent should load.

Use project skills

Keep the workflow skill in .cursor/skills/celebrant-workflow/SKILL.md so the agent can apply the same method each time.

Read docs before coding

The agent should read the brief, guidelines, and build docs before touching the React app.

Keep the docs current

If the workflow changes, update the docs and the skill together so future agents do not drift.

Folder Map

What each top-level folder is for

  • docs/: canonical project documents and reusable templates
  • intake/: raw files and rough extraction notes
  • site/: the actual React build for the website
  • brochure/: brochure-specific guidance and templates
  • .cursor/skills/: project skill instructions for the agent workflow

If someone opens this repo cold, tell them to read guide.html, then AGENTS.md, then docs/celebrant-website-guidelines.md.
